# TradeMind implementation audit

Audited the existing React/Vite and FastAPI code before editing. The data flow is `app/market_data/demo.py` → `/market-data/candles` and `/indicators` in `app/main.py` → `app/analysis/indicators.py` and `analysis/smc.py` → `PriceChart.tsx` and dashboard state in `App.tsx`. AI chat is served by `/api/v1/ai/chat` in `app/main.py`.

| Confirmed finding | Evidence in original implementation | Correction made | Regression coverage |
| --- | --- | --- | --- |
| Synthetic random volume was treated as available volume and fed into VWAP. | `market_data/demo.py` emitted random `volume` plus `volume_available: true`; `main.py` passed it into `vwap`. | DEMO candles now explicitly carry no volume. VWAP requires exchange or tick volume and supports explicit session resets. | `test_data_integrity.py`, `test_indicators.py`, `test_api.py` |
| Candle starts were aligned to the current minute, not the requested bar interval; the latest synthetic bar could be in progress. | `demo.candles` used `datetime.now(...).replace(second=0)` then stepped by timeframe. | Generate timestamps on UTC timeframe boundaries and return completed bars only. | `test_data_integrity.py`, `test_api.py` |
| Candle shape and integrity were provider assumptions, not validated at the shared boundary. | Provider protocol returned unvalidated dictionaries; API responses omitted instrument/timeframe/source tags on each candle. | Add common UTC normalizer with OHLC, volume, duplicate, ordering, interval, and missing-bar checks; gaps are warnings and are not filled. | `test_data_integrity.py` |
| FVGs had only indices, lacked symbol/timeframe/source timestamps, and the response described mitigation as the near edge while code checked the far edge. | `analysis/smc.py::detect_fvgs`; `main.py::get_fvgs`. | Zones now carry deterministic IDs, instrument, timeframe, source, all three source timestamps, mitigation and invalidation statuses; rule text documents full mitigation at the far edge. | `test_smc.py`, `test_api.py` |
| The AI received only the raw user message, so it had no actual candle or analysis results to ground its answer. | `main.py::ai_chat` passed `input=message`. | Attach backend-generated DEMO context (recent candles, indicators, FVGs, confirmed swings, strategy, warnings); reject live-analysis requests under the DEMO provider. | `test_api.py` (mocked SDK; no live API call) |
| Frontend retained the previous instrument/timeframe data during a request and after a failed request; late responses could overwrite a newer selection. | `App.tsx::load` only replaced data on full success and had no response sequence check. | Clear selected analysis while reloading and ignore superseded responses; validate returned symbol/timeframe. | Frontend switching/error regression tests |

## Indicators and detection rules found

- EMA: SMA seed over the first period, then `alpha = 2/(period+1)` recurrence.
- RSI: Wilder-smoothed average gains/losses seeded with the first simple mean; flat = 50 and gain-only = 100.
- ATR: first true range is high-low, later ranges include previous-close gaps, Wilder smoothing seeded by a simple mean.
- MACD: 12/26 SMA-seeded EMAs by default, 9-period EMA signal seeded from the first valid line value; histogram is line minus signal.
- Bollinger: 20-period SMA and population standard deviation with 2 deviations by default.
- VWAP: typical price weighted by exchange/tick volume, reset using caller-supplied session IDs. The current DEMO provider has no volume and therefore returns unavailable. UTC date session grouping is only a fallback when a caller supplies volume; an exchange calendar is not configured.
- FVG: `low[i] > high[i-2]` bullish; `high[i] < low[i-2]` bearish. Full mitigation is a later low through the bullish lower boundary or later high through the bearish upper boundary. Detection is computed against a supplied candle window; historical as-of queries must truncate that window at the evaluation time.
- Swing pivots: strict 2-left/2-right comparison; only emitted once the two right bars exist, with the second right bar as confirmation time.

## Remaining limitations after these repairs

The app now has mechanical order-block candidate/confirmation/invalidation rules, confirmed-pivot BOS/CHoCH, pivot clustering, and liquidity-sweep rules. Those algorithms have deterministic tests but have not been calibrated against an external market dataset. A BUY/SELL evaluator now applies EMA20/50 alignment, close vs EMA20, a confirmed structure break at the latest candle, ATR availability, and a freshness cutoff; its entry is a retest of the confirmed structure level or a confirmed EMA20 pullback, its stop sits beyond the structural invalidation with an explicit ATR/tick basis, and its take-profit ladder is anchored to 1.5R/2.0R/3.0R and snapped to real structural levels, each with its own R:R. The evaluator exposes an explicit setup state (NO_SETUP, WATCHLIST, WAITING_FOR_CONFIRMATION, POTENTIAL_BUY, POTENTIAL_SELL, INVALIDATED) and never presents a watch/wait state as a confirmed signal. See `docs/phase1-setup-audit.md`. The rule is unvalidated and only runs against synthetic DEMO candles in this installation.

The dashboard now exposes backend evaluation buttons, risk sizing with caller-supplied unit metadata, and chart overlay toggles for FVGs, order blocks, and support/resistance. Paper order entry supports simulated MARKET fills, pending LIMIT orders, and side-validated stop/target fields. Migrations `0002_paper_brackets` and `0003_paper_ledger` persist brackets, per-currency virtual positions, fees, slippage, and realized P&L. Pending limits fill on a subsequent history refresh when a completed demo close crosses their limit; stops and targets close positions when a completed demo close crosses their level. This intentionally does not model intrabar order, a real broker lot, or FX conversion across quote currencies. Provider catalog and TradingView status endpoints identify only configured capabilities; Zerodha and Upstox are not connected. TradingView is link-only here. No market-data, broker, or OpenAI credentials were present in the backend environment, so no live feed or authenticated service was tested.
